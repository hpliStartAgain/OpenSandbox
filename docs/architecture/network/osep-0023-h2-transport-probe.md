# OSEP-0023 H2 transport interface probe

This test-only diagnostic investigates the first graceful-drain prerequisite
for the [credential-bound TLS proposal](https://github.com/opensandbox-group/OpenSandbox/blob/main/oseps/0023-credential-bound-tls-interception.md).
It does not enable HTTP/2 in the production credential-bound addon.
The existing HTTP/1 authority gate, revision owner, image cases, dependencies,
Fast Sandbox behavior, and public configuration are unchanged.

## Stopping point

On `mitmproxy==11.0.2`, with its installed `h2==4.1.0` and
`hyperframe==6.0.1`, the ordinary GOAWAY API closes the H2 connection state.
The diagnostic opens streams 1 and 3, produces old-stream response DATA,
and calls `BufferedH2Connection.close_connection(last_stream_id=3)`.
The resulting in-memory frame is GOAWAY on stream 0 with last-stream-id 3
and NO_ERROR, but the state has become CLOSED:

- Sending old-stream DATA, END_STREAM, or WINDOW_UPDATE raises ProtocolError.
- Receiving old-stream DATA or WINDOW_UPDATE also raises ProtocolError.
- The real `Http2Server` layer suppresses response DATA and END_STREAM once
  `is_open_for_us()` becomes false.
- The hyper-h2 client also rejects old-stream DATA after receiving GOAWAY.
  That separate test-peer limitation must not be mistaken for proxy evidence.

Each operation is reproduced with fresh unmodified dependency objects. No
socket is opened. No dependency method, transition table, or connection state
is patched. The generated bytes are parsed only in memory and are never
described as client TLS-wire evidence.

The relevant pinned interfaces are:

- [`H2Connection.close_connection`](https://github.com/python-hyper/hyper-h2/blob/v4.1.0/h2/connection.py#L1026-L1059)
  processes SEND_GOAWAY before serializing its frame.
- [`H2ConnectionStateMachine`](https://github.com/python-hyper/hyper-h2/blob/v4.1.0/h2/connection.py#L40-L210)
  has no draining state; CLOSED only accepts GOAWAY.
- [`Http2Connection.is_open_for_us`](https://github.com/mitmproxy/mitmproxy/blob/v11.0.2/mitmproxy/proxy/layers/http/_http2.py#L106-L135)
  prevents further stream output on a closed connection.

An instance-scoped wrapper can observe client stream IDs, but it cannot make
the existing protocol state machine drain after ordinary GOAWAY. Continuing
would require a separately reviewed dependency/state-machine change. Do not
reset CLOSED to OPEN, emit raw GOAWAY bytes around the state machine, or
replace graceful drain with immediate connection shutdown to make this pass.

## Run and interpret

Use the same Python environment as the Egress CI pin. From
`components/egress`:

```sh
python -m unittest discover -v -s tests -p 'test_h2_transport_runtime.py'
python -m unittest discover -v -s scripts -p 'test_h2_transport_probe.py'
python scripts/h2_transport_probe.py --artifacts /tmp/h2-transport-evidence-unique
```

The unittest checks validate the diagnostic and report contract. Their green
result is not a transport-feasibility pass. The evidence runner deliberately
returns nonzero while required live cases have not passed. An existing output
directory is never overwritten; choose a new directory per run.
This strict runner is not added to the existing CI workflow: its expected
blocked exit is not a product-regression failure.

The runner records version and source identity, the task-scoped dirty diff,
in-process operation observations, a full E0–E4 case denominator, and cleanup
scope. It does not manufacture empty client/origin logs or claim a mitmdump
process was started and reaped. Missing dependencies and version mismatch
remain explicit blockers instead of successful skips.

E2–E4 include independently testable parts, but this stopping-point change
does not implement or claim those parts. No real TLS, origin, IPC, or default
30-second drain evidence is included. Socket privileges have not been tested
by this runner. A blocked environment and a failed protocol case must remain
separate conclusions.

## Boundaries for a reviewed continuation

The internal client-ID observation seam is `HttpLayer.event_to_child` while
handling an actual `HttpStream` and its `HttpRequestHeadersHook`. Capture the
client ID there, before `Http2Client` mutates outgoing event IDs for upstream
mapping. A flow UUID, request serial, or upstream stream ID is not a client
stream ID. Dropping a flow also does not prove its END_STREAM reached a peer.

Any later admission/cutover bridge must respect the existing
Registry → Receiver lock order. Recording the stream mapping after
`acquire_request()` returns leaves a race with the IPC commit thread. The
proxy event loop alone does not serialize that thread; test synchronization
must not secretly provide the atomicity being measured.

Production acceptance still requires the full approved E0–E4 TLS-wire and
origin evidence, followed by a separate feature design and transparent-443
image coverage. This diagnostic does not justify changing the existing
required image-test denominator or adding a green CI claim for H2 support.
